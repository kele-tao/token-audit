# Roadmap

What shipped in 1.0 is listed in the README. This file is the honest list of
what did **not** ship, plus what was deliberately cut and why.

## Cut from 1.0

- **Exact tokenizer parity for every encoding.** Only cl100k-style and
  o200k-style merge tables are vendored. A p50k/r50k table was prototyped but
  dropped: the extra ~120 KB of package data bought accuracy only for legacy
  completion models that the pricing table does not cover.
- **Live pricing fetch.** Prices are a committed snapshot. A `--pricing-url`
  flag that downloads a price list was cut because the tool must work offline
  and a silently moving price is worse than a dated one. Pass `--pricing` with
  your own JSON when you need a different table.
- **Automatic prompt rewriting inside `scan`.** Early versions wrote optimised
  files during a scan. That was cut: a scan must be read-only, and rewriting is
  `optimize`'s job so a human sees the diff first.
- **Model-aware compression (LLMLingua-style).** Not attempted. It needs a
  model, a quality evaluation and a GPU; none of that belongs in a dependency
  free calculator.
- **SARIF output.** Planned but not implemented; `--format json` is stable and
  documented as the machine-readable path for 1.0.

## Known limits

- The pre-tokenizer is a pure-Python port of the published cl100k and o200k
  regexes. It is exact on the 200-sample golden set and on the held-out corpus
  used during development, but text that triggers a difference in Unicode
  property handling could drift. `token-audit accuracy` is the way to find out;
  the test suite fails if the corpus-total error exceeds 5%.
- Throughput is roughly 1-2 MB/s of prompt text on one laptop core. That is
  fine for a prompt repository and not fine for a 5 GB web crawl.
- `--cache-hit` is an assumption you supply, not something the tool can observe.
- MinHash near-duplicate detection compares each candidate against every later
  candidate (O(n^2) over prompt segments). With a few thousand segments this is
  instant; with a hundred thousand it is not. A banded LSH index is the fix.

## Next

1. Banded MinHash LSH so near-duplicate detection stays fast on very large
   prompt estates.
2. A `--budget-delta` mode on `optimize` that reports the saving against a plan
   file instead of flags, so the two commands share one traffic model.
3. SARIF output for code review integration.
4. A prompt-size pre-commit hook that fails when a file's count grows past a
   percentage.
5. An optional `p50k` merge table, generated by the same script, once the
   pricing table covers the models that need it.
